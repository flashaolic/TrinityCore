## 2026-07-16 - Map::Update Scratchpad Container Optimization & std::unordered_set Allocation Behavior
**Learning:** In TrinityCore, each `Map` instance is updated sequentially by a single thread in `MapUpdater`, making `Map` member variables safe scratchpads during `Map::Update`. However, while `std::vector::clear()` retains internal buffer capacity and eliminates heap churn on subsequent `push_back`s, `std::unordered_set::clear()` frees element nodes (retaining only bucket array allocations), so subsequent `insert()` calls still incur node allocations.
**Action:** Use `std::vector` or contiguous scratchpad containers for re-usable scratchpads when eliminating element node allocation overhead, and explicitly document thread-safety assumptions and temporary usage scope in `Map.h`.
