## 2026-08-04 - Reusable Map Member Scratchpads for Single-Threaded sequential Updates
**Learning:** In TrinityCore's MapUpdater, each Map instance is updated sequentially by a single thread at a time. This architectural pattern allows us to use Map class member variables as scratchpads (e.g., for unit visitation vectors and sets) to completely avoid hot-path heap allocation churn during player/map updates, without requiring any complex thread synchronization or mutex locks.
**Action:** Always identify opportunities to refactor local heap-allocated container variables in high-frequency update loops into reusable member variables of single-threaded/sequentially updated classes, making sure to call `.clear()` before and after use to preserve capacity and avoid holding onto stale pointers.
